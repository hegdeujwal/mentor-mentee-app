# MentorLink – Mentor–Mentee Management

A web application for a college department. Mentees keep a profile, mentors record notes, recommendations and meetings for the students assigned to them, an administrator verifies (endorses) profiles, and the Head of Department (HOD) gets a read-only overview with CSV/PDF export.

Built with Next.js 16 (App Router, TypeScript), Tailwind CSS 4, Prisma 6 with SQLite, Auth.js v5 (credentials), Zod 4, Vitest and Playwright.

## Quick start

Requires Node.js 20.9 or newer (developed on Node 24).

```bash
npm install            # also creates .env from .env.example with a random AUTH_SECRET
npx prisma migrate dev # creates prisma/dev.db and applies the migration (also runs the seed)
npm run seed           # (re)loads the demo data
npm run dev            # http://localhost:3000
```

`npm run seed` deletes all rows and re-creates the demo data, so do not run it against a database you care about.

## Environment variables

| Variable | Purpose | Default in `.env.example` |
| --- | --- | --- |
| `DATABASE_URL` | Prisma connection string | `file:./dev.db` (relative to `prisma/`) |
| `AUTH_SECRET` | Signs/encrypts the session JWT | generated by `npm install` |
| `AUTH_TRUST_HOST` | Lets Auth.js trust the request host (needed for `next start` and proxies) | `true` |
| `HOD_CAN_VIEW_PRIVATE_NOTES` | Whether the HOD may read mentors' private notes | `true` |

`.env` is git-ignored; only `.env.example` is committed.

The e2e suite builds the app and runs it on port 3100 against its own `prisma/e2e.db`, which `scripts/prepare-e2e-db.mjs` deletes and rebuilds each run (the script refuses any other `DATABASE_URL`). Install the browser once with `npx playwright install chromium`.

`node scripts/capture-screenshots.mjs <dir>` (with `BASE_URL` set) captures the screenshots used in the project report.

## Roles and what they can do

- **Mentee** – registers, edits the profile (personal, academic, about-me, achievements, parents, photo), submits it for review, reads shared notes and recommendations and acknowledges them.
- **Mentor** – sees only assigned mentees (search by name/email/USN, filter by status and semester), opens a mentee, adds private or shared notes, recommendations (category, priority, due date) and session logs.
- **Administrator** – creates users and activates/deactivates them, assigns mentors (same department only), imports mentees from CSV, endorses or requests changes with a remark, reads the audit log.
- **HOD** – read-only dashboard for their department (totals, endorsed vs pending, mentor workload, sessions, completion), opens any mentee in the department, exports CSV or PDF.

Profile status flow: `Draft → Submitted → Endorsed | Changes Requested`. A submitted profile is locked; editing an endorsed profile returns it to Draft.

## Security measures

- Passwords hashed with bcrypt (cost 12); generic login error; dummy hash compare for unknown emails.
- Login rate limit: 5 attempts per email+IP per 15 minutes (in-memory, single instance).
- Role gate in `src/proxy.ts`, **and** every page, server action and route handler re-checks the user from the database (`requireRole`, `requireMenteeAccess`, `canMentor`). A deactivated user loses access on the next request.
- Object-level checks: a mentor gets "not found" for another mentor's mentee; mentee writes are filtered by the session user's id.
- Zod validation on client and server with the same schemas.
- Server Actions are POST-only with Next.js Origin/Host checking (CSRF); Auth.js cookies are HttpOnly, SameSite=Lax, and Secure over HTTPS.
- Photo upload: JPG/PNG/WEBP only, at most 2 MB, magic-byte check, random UUID file names, stored outside `public/` in `storage/uploads/` and served only to users allowed to see that mentee.
- CSV export escapes formula-like cells; CSV import validates every row and caps the file at 512 KB.
- Security headers: CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Audit log for logins, user changes, assignments, imports, submissions, reviews, notes, sessions and exports.

## Switching to PostgreSQL

Change `provider = "sqlite"` to `"postgresql"` in `prisma/schema.prisma`, set a `postgres://` `DATABASE_URL`, delete `prisma/migrations` and run `npx prisma migrate dev --name init`. The schema uses no SQLite-specific types. Note that text search uses `contains`, which is case-insensitive in SQLite but case-sensitive in PostgreSQL. Add `mode: "insensitive"` there after switching.

## Known limitations

- The login rate limiter is in memory, so it resets on restart and is not shared across instances.
- Mentees created by CSV import get a temporary password shown once; there is no forced password change or password-reset flow yet.
- When a user opens a record they may not see, the page shows "not found" but the HTTP status is 200, because the route streams behind `loading.tsx`.
- The CSP still allows `'unsafe-inline'` scripts (Next.js inline bootstrap); a nonce-based CSP would remove that.
